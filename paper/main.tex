% ABSTRACT
% ============================================================
\begin{abstract}
Semantic communication sends the meaning a receiver needs instead of
an exact copy of the source, which can save many channel symbols. In
multi-task semantic communication, one transmitted message serves
several tasks at the receiver at the same time, and these tasks
compete for a limited number of channel symbols. The best way to share
them is not fixed: the channel quality changes over time, some
sentences are harder than others for a given task, and the operator
may change the importance of each task while the system runs. Systems
that give each task a fixed share, or always send the same number of
symbols, waste symbols on clean channels and leave tasks short of
symbols on noisy ones. We therefore decide, for every sentence and
before the channel, how many symbols each task receives. Each task
owns learnable task tokens inside a FinBERT encoder, and only its
first tokens are sent. A small allocator chooses the number of tokens
per task from the sentence, the average signal-to-noise ratio reported
by the receiver and the operator priority, under a total cap and a
price per token. A nonnegative gain guarantees that raising a task's
priority never lowers its score. Simulation results on a three-task
financial corpus over AWGN and Rayleigh fading channels show that the
allocator reaches the accuracy of fixed splits with about 40 percent
fewer symbols, and that the proposed priority input steers accuracy
toward the prioritized task more strongly than a standard priority
embedding.

% ============================================================
% I. INTRODUCTION
% ============================================================
\section{Introduction}
\label{sec:intro}

Semantic communication sends the meaning of a message instead of its
raw bits. The goal is to use fewer channel symbols while keeping the
downstream tasks accurate \cite{gunduz2023beyond}. Learned systems
such as DeepSC \cite{xie2021deepsc} and its multi-task versions
\cite{sheng2024multitask} train the semantic encoder, the channel code
and the task heads together. When several tasks are answered from the
same sentence, a practical question appears: how many symbols does
each task need, for this sentence, on this channel and with this
priority?

In our earlier study, the tasks shared one decoded representation, and
the split between tasks was made after the channel with soft masks.
This did not work well. Only a hard equal split improved results on
every channel, and doubling the channel rate without controlling the
split made accuracy worse. We drew two lessons from it. First, the
split should be made before the channel, in units that each belong to
a single task. Second, more symbols do not always help, so the number
of symbols sent should itself be a decision.

This paper puts both lessons into practice. Each task owns learnable
task tokens inside the encoder. The transmitter sends only the first
$k_t$ tokens of task $t$, and a small allocator chooses the counts
$(k_1, \ldots, k_T)$ for every sentence from the sentence, the average
signal-to-noise ratio (SNR), the channel type and the priority, under
a total cap and a price per token. The tasks are sentiment analysis,
forward-looking statement (FLS) detection and environmental, social
and governance (ESG) classification of financial sentences. Our
contributions are the following.

\begin{enumerate}
  \item An encoder-side multi-task design. Each task owns ordered task
        tokens with restricted attention, each token is coded into
        four complex symbols by a channel encoder of its own task, and
        the number of tokens per task is fixed before transmission.
  \item A learned allocator in which priority enters through a
        nonnegative gain that depends on the context. This guarantees
        that a task's score never drops when its own priority rises,
        and in our tests it steers accuracy toward the prioritized
        task much more than a priority embedding does.
  \item An evaluation on a cleaned three-task financial corpus over
        additive white Gaussian noise (AWGN), Rayleigh and Rician
        channels, with the same noise for
        every method, three seeds and paired-bootstrap confidence
        intervals. It covers token saturation, splitting a fixed cap,
        variable-rate operation, priority steering, larger token
        budgets and an ablation of every allocator input.
\end{enumerate}

\section{System Model}
\label{sec:system}

Fig.~\ref{fig:arch} shows the full pipeline. A sentence $x$ is
answered for $T{=}3$ tasks: Sentiment (3 classes), FLS (3 classes)
and ESG (4 classes: environmental, social, governance, none).

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{architecture.png}
  \caption{The full pipeline. The transmitter encodes the sentence
           together with the task tokens, the allocator decides how
           many task tokens each task sends, and each kept token is
           coded into four complex symbols. The receiver equalizes the
           signal, uses the header to split the symbols by task,
           decodes each token and combines the tokens of each task
           before its head.}
  \label{fig:arch}
\end{figure*}

\subsection{Task Tokens and Encoder}

Each task owns $J$ learnable task-token vectors, so there are $TJ$
task tokens in total. The encoder input is \texttt{[CLS]}, then the
$TJ$ task tokens, then the word pieces of the sentence. Attention is
restricted. A task token looks at the words and at the tokens of its
own task. The words, \texttt{[CLS]} and \texttt{[SEP]} look only at
the words. The words therefore never see the task tokens, which keeps
the word processing the same as in the pretrained encoder, and tokens
of different tasks never share information. The encoder is FinBERT
\cite{yang2020finbertfls} (\texttt{finbert-pretrain}, 110M parameters,
hidden size $d{=}768$). We keep the \texttt{[CLS]} output as a summary
of the sentence and the $TJ$ task-token outputs. The word outputs are
not used.

\subsection{Token Selection and Channel Coding}

Given counts $k_t \in \{1, \ldots, J\}$, the transmitter keeps the
first $k_t$ tokens of task $t$ and never sends the others. A channel
encoder that belongs to task $t$ ($768 \to 256 \to 8$ real values,
with a rectified linear unit, ReLU) maps each kept token to $L{=}4$ complex symbols, normalized to
an average energy of one per symbol. A sentence therefore uses
$N = 4 \sum_t k_t$ symbols. A short header carries the counts and is
assumed to arrive without errors.

\subsection{Channel and Receiver}

The channel is $y = h x + n$ with $n \sim \mathcal{CN}(0, \sigma^2)$
and $\sigma^2 = 10^{-\mathrm{SNR}/10}$. The fading is drawn
independently for each symbol. AWGN uses $h{=}1$, Rayleigh uses
$h \sim \mathcal{CN}(0,1)$, and Rician uses
$h = \sqrt{K/(K{+}1)}\,e^{j\theta} + \sqrt{1/(K{+}1)}\,\mathcal{CN}(0,1)$
with $K{=}4$. All three have $\mathbb{E}|h|^2 = 1$. The receiver knows
$h$ and applies zero forcing, $\hat{x} = y/h$, as in DeepSC
\cite{xie2021deepsc}. On AWGN, zero forcing changes nothing. The
header tells the receiver how to split the symbols back into task
tokens. A channel decoder for each task ($8 \to 256 \to 768$) rebuilds
each token. An attention pooling layer for each task, with a learned
query, combines the received tokens of that task and ignores the
tokens that were not sent. Finally, one linear layer per task gives
the prediction.

\subsection{Channel Quality Feedback}

The receiver reports the average SNR back to the transmitter as
channel quality information (CQI). The
allocator uses this average and the channel type, but never the fading
of individual symbols. In the simulation, the reported SNR is the true
SNR of the sentence.

% III. ALLOCATION
% ============================================================
\section{Token Allocation}
\label{sec:alloc}

\subsection{Problem}

Let $\mathbf{w} = (w_1, \ldots, w_T)$ be the priorities, with
$w_t \geq 0$ and $\sum_t w_t = 1$. Given a total cap $K$ and a
per-task maximum $J_{\max}$, the allocator chooses integer counts that
minimize
\begin{equation}
  \mathbb{E}\Big[\sum_{t=1}^{T} w_t\, \mathrm{CE}_t(k_t)
              + \lambda \sum_{t=1}^{T} k_t\Big]
  \quad \text{s.t.} \quad
  1 \leq k_t \leq J_{\max}, \;\; \sum_t k_t \leq K,
  \label{eq:problem}
\end{equation}
where $\mathrm{CE}_t(k_t)$ is the cross-entropy of task $t$ when it
sends $k_t$ tokens and $\lambda \geq 0$ is a price per task token.
With $\lambda{=}0$ the allocator only moves tokens between tasks under
the cap. With $\lambda{>}0$ it may also send fewer tokens than the cap
allows. The cap is an outside resource limit and is not learned.

When each $\mathrm{CE}_t$ has diminishing returns in $k_t$, problem
\eqref{eq:problem} is solved by greedy marginal allocation
\cite{fox1966marginal}: start with one token per task, and keep giving
the next token to the task with the largest weighted loss reduction
$w_t\,[\mathrm{CE}_t(k_t) - \mathrm{CE}_t(k_t{+}1)]$, until this
reduction is no larger than $\lambda$ or a limit is reached. Here
$\lambda$ acts as the Lagrange multiplier of the symbol budget. We
apply this rule to the losses of each test sentence, computed with
its true labels and its actual noise, to get a hindsight oracle. The
oracle cannot be built in practice and is shown only as an upper
bound.

\subsection{Learned Allocator}

The allocator receives the \texttt{[CLS]} output (768 values), the SNR
in dB divided by 10 and passed through a linear layer with ReLU to 32
values, the channel type as a one-hot vector passed to 32 values, and
the priority vector $\mathbf{w}$. As an option it also receives a
confidence input: for each task, the normalized entropy of that task's
head when all its tokens go through a noise-free channel. It is
computed at the transmitter and no gradient flows through it. The
inputs are joined and passed through one hidden layer of 128 ReLU
units, which gives a vector $\mathbf{u}$. Two linear layers then give
a base score $b_t(\mathbf{u})$ and a raw gain $g_t(\mathbf{u})$ for
each task. The score of task $t$ is
\begin{equation}
  s_t = b_t(\mathbf{u}) + \mathrm{softplus}\big(g_t(\mathbf{u})\big)\, w_t .
  \label{eq:score}
\end{equation}
The base score says how many tokens the task needs for this sentence
and channel. The gain says how much the priority should count in this
situation. The priority does not enter the hidden layer.

\begin{proposition}
\label{prop:monotone}
For any sentence, SNR, channel type and network weights, the score
$s_t$ in \eqref{eq:score} never decreases when the task's own priority
$w_t$ increases.
\end{proposition}
\begin{IEEEproof}
$\mathbf{u}$ does not depend on $\mathbf{w}$, so
$\partial s_t / \partial w_t = \mathrm{softplus}(g_t(\mathbf{u})) \geq 0$.
\end{IEEEproof}

Equation \eqref{eq:score} is a varying-coefficient model
\cite{hastie1993varying}: the score is linear in $w_t$, and both its
intercept and its slope depend on the context, as in networks that
produce their own coefficients \cite{alvarezmelis2018senn}. Using
softplus to keep the slope positive follows \cite{dugas2001softplus},
and the guarantee is a case of partial monotonicity
\cite{sill1998monotonic, daniels2010monotone}. A standard design that
feeds $\mathbf{w}$ into the hidden layer gives no such guarantee. We
compare with it in Section~\ref{ssec:priority}.

The scores are turned into counts by fixed steps. The soft counts are
$c_t = 1 + (J_{\max} - 1)\,\sigma(s_t)$. If $\sum_t c_t > K$, the part
above one token is scaled down,
$c_t \leftarrow 1 + (c_t - 1)(K - T)/(\sum_j c_j - T)$. The counts are
then rounded to the nearest integer. If the rounded total is above the
cap, all counts are rounded down and the remaining tokens go to the
largest fractional parts, with ties broken by priority. The output
layers start at zero and the gain bias at $-5$, so training starts from
an almost equal split for any priority.

Rounding has no useful gradient, so training uses a straight-through
estimator \cite{bengio2013estimating}. The forward pass uses the
rounded counts and hard token masks. The backward pass uses the soft
counts and soft masks $m_{t,j} = \sigma\big((c_t - j + 0.5)/\tau\big)$
with $\tau = 0.3$. The priorities are drawn at random for each batch,
$\mathbf{w} \sim \mathrm{Dir}(1,1,1)$, so that one model serves every
priority at run time, as in loss-conditional training
\cite{dosovitskiy2020yoto, navon2021pareto}.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Data}

We use the Financial PhraseBank \cite{malo2014phrasebank}
(\texttt{Sentences\_50Agree}, 4,846 sentences) with its human
sentiment labels. The FLS and ESG labels come from the FinBERT-FLS and
FinBERT-ESG classifiers \cite{huang2023finbert}, so these two tasks
contain some label noise. We repair 111 sentences whose accented
characters were broken by an encoding error. We remove exact
duplicates (keeping one copy when the labels agree and none when they
conflict), near-duplicates that differ only in numbers and have
conflicting sentiment labels, and four fragments shorter than four
tokens. This leaves 4,825 sentences. The class counts are
600/2,865/1,360 for negative/neutral/positive sentiment,
3,715/92/1,018 for not-FLS/nonspecific/specific FLS, and
299/893/53/3,580 for environmental/social/governance/none ESG.

The corpus is split 70/10/20 into 3,379 training, 480 validation and
966 test sentences. The split is stratified by the joint label of the
three tasks. Sentences that differ only in numbers are kept in the
same split, so no sentence template appears in both training and
test. Every run uses the same split.

\subsection{Training}

Training has two stages. In the first stage, the encoder, task tokens,
channel encoders and decoders, pooling layers and heads are trained
for 12 epochs with nested dropout \cite{rippel2014nested}. For every
sentence and task, a cut-off $j$ is drawn uniformly from
$\{1, \ldots, J\}$ and only the first $j$ tokens are sent, which
teaches the first token to carry the most information. The channel
type is drawn for each batch and the SNR for each sentence, uniformly
in $[-10, 10]$\,dB. The loss is the sum of the three cross-entropies.
FLS and ESG use inverse-frequency class weights computed on the
training split and scaled to an average of one, so no task's loss is
made smaller than another's. We use AdamW with learning rate
$2{\times}10^{-5}$ for the encoder and $10^{-3}$ for the rest, batch
size 16, and keep the epoch with the lowest validation loss.

In the second stage, the pipeline is frozen, the encoder outputs are
computed once, and only the allocator is trained for 30 epochs (AdamW,
learning rate $10^{-3}$, batch size 16) on \eqref{eq:problem} with
random channel, SNR and priority. After each epoch the same objective,
including $\lambda$ times the number of tokens, is measured on the
validation split with fixed noise and equal priority, and the best
epoch is kept. We also tried training the allocator together with the
pipeline in a single stage; Section~\ref{ssec:fixedcap} explains why we did
not keep that approach.

\subsection{Evaluation}

The test SNRs are $\{-15, -10, -5, -2, 0, 2, 5, 10, 15, 20\}$\,dB. For
each test batch, channel and SNR, one fading and noise realization is
drawn from a fixed seed and used by every method, so all methods see
exactly the same channel. Every setting is trained with three seeds.
Accuracy is given per task and as the mean of the three tasks.
Confidence intervals are paired-bootstrap 95\% intervals with 10,000
resamples over (seed, channel, SNR, sentence). All baselines run on
the same frozen pipeline: fixed splits without an allocator, the equal
split at the cap, the proportional split $\mathrm{round}(K\mathbf{w})$,
a random split with the same total as the allocator, and the hindsight
oracle.

We study two token budgets. In the main setting, each task owns $J{=}4$
tokens (12 task tokens, at most 48 symbols) and all three channels are
used. In the large-budget setting, each task owns $J{=}32$ tokens
(96 task tokens), the per-task maximum is $J_{\max} = K/2$, training
and testing use AWGN only, and the channel-type input is removed.

\subsection{Fixed Cap: Splitting Eight Tokens}
\label{ssec:fixedcap}

symbols, and the methods differ only in how they split the eight
tokens (Table~\ref{tab:cap8}). All practical methods are within 0.25

With the confidence input it is $0.19$ points above, with the same

There is little to gain from splitting a fixed cap differently. Using
the measured per-task curves, the best fixed split chosen in hindsight

\subsection{Priority Steering}
\label{ssec:priority}

To check that the operator's priority really steers the allocation,
we evaluate the cap-8 models at 0\,dB while raising the ESG priority
from 0.1 to 0.9, with the other two tasks sharing the rest equally
(Table~\ref{tab:priority}). With the gain form \eqref{eq:score}, ESG
tokens rise steadily from 2.27 to 3.59 and ESG accuracy from 85.3 to
87.1 percent, and no sentence gets fewer ESG tokens when its ESG
priority goes up. Sentiment and FLS give up 1.2 and 0.9 points. The
same allocator with the priority fed into the hidden layer moves ESG

\subsection{Larger Token Budgets on a Gaussian Channel}
\label{ssec:awgn}

To check that the pipeline and the allocator work over a wide range of
budgets, each task gets $J{=}32$ tokens (96 task tokens), training and
testing use AWGN only, the channel-type input is removed, and the cap
takes the values $K \in \{8, 16, 32, 64\}$ with per-task maximum
$J_{\max} = K/2$. Without an allocator, accuracy grows steadily with
the number of tokens per task: 78.74 percent with one token
(12 symbols), 84.11 with four (48), 86.88 with sixteen (192) and 87.55
with all 32 (384 symbols). Most of the late gain comes from very low
SNR. At $-15$\,dB accuracy grows from 47.8 to 81.7 percent between one
and 32 tokens per task, while from 5\,dB upward two tokens per task
are already as good as 32 (88.3 percent at 5\,dB).

Table~\ref{tab:awgn} compares sending every token, the equal split at
each cap and the learned allocator. At $K{=}16$ the allocator reaches
84.65 percent with 39.1 symbols, while the equal split reaches 84.73
percent with 64 symbols. This is 39 percent fewer symbols for the
same accuracy. At $K{=}32$ and $K{=}64$ it saves 63 and 80 percent of
the symbols and loses 0.6 and 1.4 points. At $\lambda{=}0.01$ the
savings grow to 76 and 87 percent. On clean channels (10\,dB and
above) it sends 12 to 16 symbols at caps 16, 32 and 64
(Table~\ref{tab:awgn16}). At $K{=}8$ with $\lambda{=}0.003$ the
allocator still sends about 32 symbols at every SNR, so this price is
too low to save symbols at that cap. At $\lambda{=}0.01$ it sends 22.1
symbols.

training, the priority-weighted cross-entropy plus $\lambda$ times the

\emph{The SNR input is essential.} Without it the allocator cannot
change its rate: it sends about 58 symbols at every SNR, its objective
is worse by 0.034 to 0.039 (paired 95\% intervals exclude zero) and
its weighted accuracy is lower by 0.40 to 0.61 points. With the SNR
input, the allocator goes from about 63 symbols at $-10$\,dB to 12 at
$+20$\,dB.

\emph{The priority input is useful.} Without it, ESG tokens do not
change when ESG is prioritized. Removing it from the full allocator
worsens the objective by 0.010 ($[0.008, 0.012]$) and lowers the
weighted accuracy by 0.26 points ($[-0.34, -0.18]$). With it, ESG
tokens rise from 3.40 to 4.60 and ESG accuracy from 82.6 to 83.6
percent under ESG priority.

\emph{The sentence summary gives a small but significant gain.} It is
the only input that makes the allocation differ between sentences at
the same SNR and priority (a standard deviation of about 1.5 tokens,
against zero without it). Removing it worsens the objective by 0.011
($[0.009, 0.014]$) and lowers the weighted accuracy by 0.14 points
($[-0.23, -0.05]$). Without the sentence summary, the response to
priority is also much weaker (ESG tokens 3.53 to 3.77).

\emph{The confidence input adds very little.} Added to the full
allocator, it lowers the objective by 0.002 ($[-0.0035, -0.0006]$) and
the number of symbols by 1.8, with no significant change in weighted
accuracy.

\subsection{Data Checks and Limitations}
\label{ssec:limits}

We checked that the training, validation and test splits do not
overlap and together cover the whole corpus, that no sentence template
appears in more than one split, that every reported result uses the
966 test sentences, that the labels stored with each prediction match
the corpus, and that the class weights use the training split only.
One test sentence is six word pieces longer than the 128 word-piece
limit and is cut the same way for every method.

The FLS and ESG labels come from classifiers and contain errors: 161
FLS and 365 ESG labels have a classifier confidence below 0.6. The
rarest classes have few test examples (17 nonspecific FLS and 10
governance ESG sentences), so per-class results for them are
uncertain. The training SNR range does not cover $-15$\,dB, where the
allocator sends too few tokens in the large-budget setting. The price
$\lambda$ was chosen from a sweep, not derived from an accuracy
target.
