% ============================================================
% ABSTRACT
% ============================================================
\begin{abstract}
Semantic communication sends the meaning a receiver needs instead of
an exact copy of the source, saving channel symbols. In multi-task
semantic communication, one transmitted message serves several tasks
at the receiver, and these tasks compete for a limited number of
channel symbols. The best way to share them is not fixed: the channel
quality changes over time, some sentences are harder than others for a
given task, and the operator may change the importance of each task at
run time. Systems that give each task a fixed share, or always send the
same number of symbols, waste symbols on clean channels and starve
tasks on noisy ones. We therefore decide, for every sentence and
before the channel, how many symbols each task receives. Each task
owns learnable task tokens inside a FinBERT encoder, and only its
first tokens are sent. A small allocator chooses the number of tokens
per task from the sentence, the average signal-to-noise ratio reported
by the receiver and the operator priority, under a total cap and a
price per token. A nonnegative gain guarantees that raising a task's
priority never lowers its score. Simulation results on a three-task
financial corpus show that the allocator keeps the accuracy of an
equal split with 45 percent fewer symbols on an AWGN channel, sends 26
percent fewer symbols on a Rayleigh fading channel at a cost of 0.24
accuracy points, and steers accuracy toward the prioritized task.
\end{abstract}

\begin{IEEEkeywords}
Semantic communication, multi-task learning, resource allocation,
task tokens, adaptive rate, FinBERT.
\end{IEEEkeywords}

% ============================================================
% I. INTRODUCTION
% ============================================================
\section{Introduction}
\label{sec:intro}

Semantic communication sends the meaning of a message instead of its
raw bits, so that fewer channel symbols are needed to keep the
downstream tasks accurate \cite{gunduz2023beyond}. Learned systems such
as DeepSC \cite{xie2021deepsc} train the semantic encoder, the channel
code and the receiver together. Many applications need several answers
from the same message. A financial sentence, for example, can be read
at once for its sentiment, for whether it makes a forward-looking
statement (FLS) and for its environmental, social or governance (ESG)
topic. Sending one message for all tasks saves symbols, but the tasks
then compete for the same channel uses, and the best share keeps
changing: a clean channel needs few symbols while a noisy one needs
many, a sentence that is easy for one task can be hard for another,
and the operator may favour one task for a while. A fixed share per
task, or a fixed number of symbols, wastes symbols when the channel is
good and starves the important tasks when it is bad.

Multi-task semantic systems share one encoder among the tasks
\cite{sheng2024multitask, zhang2024udeepsc}. U-DeepSC
\cite{zhang2024udeepsc} adapts the number of transmitted features to
the noise level but serves one task per transmission, and Shao
\emph{et al.} \cite{shao2022learning} adapt the feature length to the
channel for a single task. In our earlier study, the split between
tasks was made after the channel, with soft masks on a shared
representation. Only a hard equal split helped, and doubling the rate
without controlling the split made accuracy worse. The split should
therefore be made before the channel, in units owned by one task, and
the number of symbols should itself be a decision.

We follow both lessons. Each task owns ordered task tokens inside the
encoder, and a small allocator decides, for every sentence, how many of
them each task sends, from the sentence, the average signal-to-noise
ratio (SNR) and the operator priority, under a total cap and a price
per token. Our contributions are the following.

\begin{enumerate}
  \item An encoder-side multi-task design. Each task owns ordered task
        tokens with restricted attention, coded by a channel encoder of
        its own task, and the number of tokens per task is fixed before
        transmission.
  \item A learned allocator in which the priority enters through a
        nonnegative, context-dependent gain. This guarantees that
        raising a task's priority never lowers its score. The integer
        counts are trained end to end with a straight-through
        estimator.
  \item An evaluation on a three-task financial corpus over AWGN and
        Rayleigh fading channels, with the same noise for every method,
        a price chosen on validation data only, three seeds and
        paired-bootstrap confidence intervals.
\end{enumerate}

% II. SYSTEM MODEL AND TOKEN ALLOCATION
% ============================================================
\section{System Model and Token Allocation}
\label{sec:system}

As shown in Fig.~\ref{fig:arch}, the transmitter maps a sentence $s$
into a stream of complex symbols $\mathbf{x}$, and the receiver answers
$T{=}3$ tasks from the received signal $\mathbf{y}$: Sentiment (3
classes), FLS (3 classes) and ESG (4 classes: environmental, social,
governance, none).

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{architecture.pdf}
  \caption{The full pipeline. The size of the data leaving each block
           is written above it. The allocator decides how many task
           tokens each task sends, and only those tokens are coded into
           channel symbols. The receiver equalizes the signal, uses the
           header to split the symbols by task, decodes each token and
           combines the tokens of each task before its head.}
  \label{fig:arch}
\end{figure*}

\subsection{Transmitter, Channel and Receiver}

\textit{Semantic encoder:} Each task $t$ owns $J$ learnable task
tokens, placed after \texttt{[CLS]} and before the word pieces of $s$.
The encoder is FinBERT \cite{yang2020finbertfls}
(\texttt{finbert-pretrain}, $d{=}768$) with restricted attention: a
task token looks at the words and at the tokens of its own task, while
the words look only at the words. The word processing therefore stays
as in the pretrained model, and the tasks never share information
through their tokens. The encoder outputs the \texttt{[CLS]} vector
$\mathbf{c} \in \mathbb{R}^{d}$, a summary of the sentence, and one
vector $\mathbf{z}_{t,j} \in \mathbb{R}^{d}$ per task token.

\textit{Allocator:} From $\mathbf{c}$, the average SNR $\gamma$ reported
by the receiver and the priority $\mathbf{w}$, the allocator chooses
the counts $\mathbf{k} = A_{\theta}(\mathbf{c}, \gamma, \mathbf{w})$,
with $1 \le k_t \le J_{\max}$ and $\sum_t k_t \le K$
(Sections~\ref{ssec:problem} and \ref{ssec:allocator}). Task $t$ keeps
its first $k_t$ tokens; the others are never encoded.

\textit{Channel encoder and channel:} A channel encoder for each task
($768 \to 256 \to 8$, with a rectified linear unit, ReLU) maps each kept
token to $L{=}4$ complex symbols with an average energy of one per
symbol. The kept tokens of all tasks form a stream of
$N = 4\sum_t k_t$ symbols \cite{bourtsoulatze2019deep}, preceded by a
short header that carries $\mathbf{k}$ and is assumed to arrive
without errors. Unlike DeepSC, where the stream length is fixed
\cite{xie2021deepsc}, $N$ here depends on the sentence, the channel and
the priority. The channel is
\begin{equation}
  \mathbf{y} = \mathbf{h} \odot \mathbf{x} + \mathbf{n},
  \label{eq:channel}
\end{equation}
where $\odot$ is the element-wise product,
$\mathbf{n} \sim \mathcal{CN}(\mathbf{0}, \sigma^2 \mathbf{I}_N)$ and
$\sigma^2 = 10^{-\gamma/10}$. The AWGN channel uses
$\mathbf{h} = \mathbf{1}$, and the Rayleigh channel draws every entry
of $\mathbf{h}$ independently from $\mathcal{CN}(0,1)$. The two
channels are studied separately.

\textit{Receiver:} The receiver knows $\mathbf{h}$ and applies zero
forcing, $\hat{\mathbf{x}} = \mathbf{y} \oslash \mathbf{h}$, as in
DeepSC \cite{xie2021deepsc}. Using the header, it cuts
$\hat{\mathbf{x}}$ into blocks of four symbols, and a channel decoder
for each task ($8 \to 256 \to 768$) rebuilds each token. An attention
pooling layer for each task, with a learned query, combines the
received tokens of that task and ignores the tokens that were not
sent, and a linear head gives the prediction. The receiver reports the
average SNR back as channel quality information (CQI); the allocator
never sees the fading of individual symbols.

\textit{How the blocks are linked:} The counts $\mathbf{k}$ are the only
interface between the allocator and the rest of the system. At the
transmitter they decide which task tokens are encoded, and through the
header they tell the receiver how to cut the stream and which tokens
each pooling layer may use. Because the tokens are ordered
(Section~\ref{sec:setup}), the first $k_t$ tokens are the most useful
ones, so $\mathbf{k}$ alone describes what was sent. The tasks interact
only through the shared encoder weights and the shared budget of the
allocator. The pipeline is trained first, with random counts; it is
then frozen, and only the allocator is trained.

\subsection{Allocation Problem}
\label{ssec:problem}

Let $\mathbf{w} = (w_1, \ldots, w_T)$ be the priorities, with
$w_t \geq 0$ and $\sum_t w_t = 1$. Given a total cap $K$ and a
per-task maximum $J_{\max}$, the allocator chooses integer counts that
minimize
\begin{equation}
  \begin{aligned}
    & \mathbb{E}\Big[\sum_{t=1}^{T} w_t\, \mathrm{CE}_t(k_t)
                   + \lambda \sum_{t=1}^{T} k_t\Big] \\
    & \text{s.t.} \quad 1 \leq k_t \leq J_{\max}, \;\; \sum_{t=1}^{T} k_t \leq K,
  \end{aligned}
  \label{eq:problem}
\end{equation}
where $\mathrm{CE}_t(k_t)$ is the cross-entropy of task $t$ when it
sends $k_t$ tokens and $\lambda \geq 0$ is a price per task token.
With $\lambda{=}0$ the allocator only moves tokens between tasks under
the cap; with $\lambda{>}0$ it may also send fewer tokens than the cap
allows. When each $\mathrm{CE}_t$ has diminishing returns in $k_t$,
\eqref{eq:problem} is solved by greedy marginal allocation
\cite{fox1966marginal}: starting from one token per task, the next
token goes to the task with the largest weighted loss reduction
$w_t\,[\mathrm{CE}_t(k_t) - \mathrm{CE}_t(k_t{+}1)]$, until this
reduction falls below $\lambda$ or a limit is reached. The price
$\lambda$ thus decides when an extra token is no longer worth
sending.

\subsection{Learned Allocator}
\label{ssec:allocator}

The \texttt{[CLS]} output $\mathbf{c}$ and the SNR $\gamma/10$, passed
through a linear layer with ReLU to 32 values, are joined and passed
through one hidden layer of 128 ReLU units, which gives a vector
$\mathbf{u}$. Two linear layers then give a base score
$b_t(\mathbf{u})$ and a raw gain $g_t(\mathbf{u})$ for each task, and
the score of task $t$ is
\begin{equation}
  s_t = b_t(\mathbf{u}) + \mathrm{softplus}\big(g_t(\mathbf{u})\big)\, w_t .
  \label{eq:score}
\end{equation}
The base score says how many tokens the task needs for this sentence
and channel, and the gain says how much the priority should count in
this situation. The priority does not enter the hidden layer.

\begin{proposition}
\label{prop:monotone}
For any sentence, SNR and network weights, the score $s_t$ in
\eqref{eq:score} never decreases when the task's own priority $w_t$
increases.
\end{proposition}
\begin{IEEEproof}
$\mathbf{u}$ does not depend on $\mathbf{w}$, so
$\partial s_t / \partial w_t = \mathrm{softplus}(g_t(\mathbf{u})) \geq 0$.
\end{IEEEproof}

Equation \eqref{eq:score} is a varying-coefficient model
\cite{hastie1993varying} whose slope is kept positive with softplus
\cite{dugas2001softplus}, a case of partial monotonicity
\cite{daniels2010monotone}. Feeding $\mathbf{w}$ into the hidden layer
instead, as a usual priority embedding does, gives no such
guarantee.

The soft counts are $c_t = 1 + (J_{\max} - 1)\,\sigma(s_t)$. If
$\sum_t c_t > K$, the part above one token is scaled down,
$c_t \leftarrow 1 + (c_t - 1)(K - T)/(\sum_j c_j - T)$. The counts are
then rounded; if the rounded total exceeds the cap, all counts are
rounded down and the remaining tokens go to the largest fractional
parts, with ties broken by priority. The output layers start at zero
and the gain bias at $-5$, so training starts from an almost equal
split. Rounding has no useful gradient, so training uses a
straight-through estimator \cite{bengio2013estimating}: the forward
pass uses the rounded counts and hard token masks, and the backward
pass uses the soft counts and the soft masks
$m_{t,j} = \sigma\big((c_t - j + 0.5)/\tau\big)$ with $\tau = 0.3$. The
priorities are drawn for each batch from $\mathrm{Dir}(1,1,1)$, so that
one model serves every priority at run time
\cite{dosovitskiy2020yoto}.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Data and Training}

We use the Financial PhraseBank \cite{malo2014phrasebank} (sentences
with at least 50 percent annotator agreement) with its human sentiment
labels. The FLS and ESG labels come from the FinBERT-FLS and
FinBERT-ESG classifiers \cite{huang2023finbert} and contain some label
noise. After repairing 111 encoding errors and removing duplicates,
conflicting near-duplicates and short fragments, 4,825 sentences
remain; ESG is strongly imbalanced (3,580 \emph{none}, 53
\emph{governance}). They are split 70/10/20 into 3,379 training, 480
validation and 966 test sentences, stratified by the joint label, and
sentences that differ only in numbers are kept in the same split.

Each channel is trained and tested on its own, in two stages. Stage 1
trains the encoder, task tokens, channel encoders and decoders, pooling
layers and heads for 12 epochs with nested dropout
\cite{rippel2014nested}: for every sentence and task, only a random
number $j \in \{1, \ldots, J\}$ of first tokens is sent, which teaches
the first token to carry the most information. The SNR is drawn per
sentence, uniformly in $[-10, 10]$\,dB, and the loss is the sum of the
three cross-entropies, with inverse-frequency class weights for FLS
and ESG. We use AdamW (learning rate $2{\times}10^{-5}$ for the encoder
and $10^{-3}$ for the rest, batch size 16) and keep the epoch with the
lowest validation loss. Stage 2 freezes the pipeline and trains only
the allocator for 80 epochs on \eqref{eq:problem}, with random SNR and
priority. The kept epoch has the lowest validation objective at equal
priority, with every validation sentence scored at five fixed SNR and
noise draws, so that the choice is not decided by the noise of a
single draw.

\subsection{Evaluation}

Each task owns $J{=}32$ task tokens (96 in total, at most 384
symbols) and may send at most $J_{\max}{=}K/2$, so that one task can
never take the whole cap. The test SNRs are $-15$, $-10$, $-5$, $-2$, 0, 2, 5, 10,
15 and 20\,dB. For each test batch and SNR, one fading and noise
realization is drawn from a fixed seed and shared by all methods. Over
the seeds $S$, the SNRs $\Gamma$ and the test sentences $D$, that is,
over $M = |S||\Gamma||D|$ cases, the average number of symbols and the
accuracy of task $t$ are
\begin{align}
  \bar N &= \frac{1}{M}\sum_{s,\gamma,i} 4\sum_{t=1}^{T} k_t(i,\gamma,s), \label{eq:symbols}\\
  \mathrm{Acc}_t &= \frac{100}{M}\sum_{s,\gamma,i} \mathbb{1}\big[\hat y_t(i,\gamma,s) = y_t(i)\big]. \label{eq:acc}
\end{align}
The mean accuracy is the unweighted average over the tasks, as in
multi-task benchmarks \cite{wang2019glue}, cost is measured as the
average number of transmitted symbols \cite{shao2022learning}, and the
weighted accuracy $\sum_t w_t \mathrm{Acc}_t$ is used when the priority
is not equal. Differences between methods are given with
paired-bootstrap 95\% confidence intervals \cite{koehn2004statistical}
(10,000 resamples over seed, SNR and sentence). The baselines run on
the same frozen pipeline without an allocator: every task sends all
its tokens, or the cap is split equally between the tasks.

The price $\lambda$ is chosen on the validation set only. Among $\lambda \in \{0.001, 0.002, 0.003, 0.005, 0.01, 0.02\}$ at
$K{=}16$, we keep the one that sends the fewest symbols while staying
within $\epsilon{=}0.25$ points of the equal split. This is the
$\epsilon$-constraint form of \eqref{eq:problem}, whose Lagrangian is
the training loss. The test set then checks the choice with a
non-inferiority test: the lower end of the confidence interval of the
accuracy difference must lie above $-\epsilon$.

\section{Results}
\label{sec:results}

\subsection{When Extra Tokens Help}
\label{ssec:saturation}

Without an allocator, the number of tokens a task needs depends
strongly on the channel. To come within 0.5 points of its best
accuracy, each task needs 29 tokens at $-15$\,dB but a single token
from 5\,dB upward on AWGN. Deep fades make Rayleigh more demanding: 31
tokens at $-15$\,dB, 5 at 5\,dB and a single token only at 20\,dB. A
fixed number of tokens therefore either wastes symbols on clean
channels or starves noisy ones.

\subsection{Choice of the Price}
\label{ssec:price}

Table~\ref{tab:price} gives the validation results used to choose
$\lambda$. A higher price makes the allocator send fewer symbols and
lose more accuracy. On both channels, $\lambda{=}0.01$ and $0.02$ lose
more than $\epsilon{=}0.25$ points and are excluded, and
$\lambda{=}0.005$ is the remaining price with the fewest symbols. It
is selected on both channels and used in all the results below.

\subsection{The Three Benchmarks}
\label{ssec:bench}

Table~\ref{tab:bench} compares, on the test set, sending every token
with no allocator and no cap, the equal split at $K{=}16$ with no
allocator, and the allocator at $K{=}16$. On AWGN the allocator sends
45 percent fewer symbols than the equal split (35.1 against 64) with
no measurable loss of accuracy ($-0.05$ points,
$[-0.16, +0.06]$), so it passes the non-inferiority test. On Rayleigh
it sends 26 percent fewer symbols (47.1 against 64) for $-0.24$ points
($[-0.35, -0.12]$). This price sat exactly at the margin on
validation, and on the test set it misses the non-inferiority test by
0.1 points. Sending every token is more accurate, by 2.8 points on
AWGN and 4.7 points on Rayleigh, but costs 384 symbols per sentence.

Fig.~\ref{fig:bench} shows where the savings come from. The allocator
sends almost the whole cap at low SNR, where every token helps, and
lowers its rate as the channel improves: from 64 to 12 symbols per
sentence on AWGN and from 63 to 17 on Rayleigh, which needs more
symbols than AWGN at every SNR, as the saturation results predict. At
every SNR its accuracy stays within 0.6 points of the equal split. The
advantage of sending every token is concentrated at low SNR ($-15$ and
$-10$\,dB on AWGN, up to $-5$\,dB on Rayleigh), where the cap of 16
tokens limits both the equal split and the allocator.

\subsection{Effect of the Cap}
\label{ssec:caps}

Fig.~\ref{fig:caps} repeats the comparison with the equal split for
caps of 8, 16, 32 and 64 tokens, at the same price. The saving grows
with the cap, from 26 to 83 percent on AWGN and from 1 to 72 percent
on Rayleigh, because a larger cap lets the equal split send more
tokens that the channel does not need. At caps 8 and 16 the accuracy
is unchanged on AWGN; on Rayleigh, cap 8 is even more accurate than
the equal split ($+0.27$ points, $[0.11, 0.42]$) because the allocator
moves tokens between tasks. At caps 32 and 64 the allocator gives up
0.6 to 2.0 points in exchange for the larger savings.

  \centering

           $\lambda{=}0.005$, test set: symbols saved (left) and
           accuracy difference with 95\% confidence intervals (right).}
  \label{fig:caps}
\end{figure}

\subsection{Priority Steering}
\label{ssec:priority}

To check that the operator's priority steers the allocation, we raise
the ESG priority from 0.1 to 0.9, with the other two tasks sharing the
rest equally, at $-10$, $-5$ and 0\,dB and $K{=}16$. The average
number of ESG tokens rises from 3.5 to 7.0 on AWGN and from 4.0 to 7.6
on Rayleigh, and the ESG accuracy rises by 4.59 points
($[3.98, 5.20]$) and 8.27 points ($[7.50, 9.04]$). No sentence ever
receives fewer ESG tokens when the ESG priority rises, in line with
Proposition~\ref{prop:monotone}.

% ============================================================
% V. CONCLUSION
% ============================================================
\section{Conclusion}
\label{sec:conclusion}

We moved the split between tasks in multi-task semantic communication
to the transmitter. Each task owns ordered task tokens, and a small
allocator decides for every sentence how many of them each task sends,
from the sentence, the average SNR and the priority, under a cap and a
price per token, with a priority input that provably never works
against the chosen task. The allocator follows the channel: it sends
almost the whole cap on noisy channels and few symbols on clean ones.
It keeps the accuracy of an equal split with 45 percent fewer symbols
on AWGN, uses 26 percent fewer on Rayleigh fading at a small accuracy
cost, and steers accuracy toward the prioritized task. The FLS and ESG
labels come from classifiers, the training SNR range does not cover
$-15$\,dB, and the transmitter knows the average SNR without error.
Future work will consider imperfect channel reports, a dataset with
human labels for every task, and frequency-selective channels, where
the transmitter could also choose which channel uses carry each task.
